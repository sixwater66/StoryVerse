# 统一数据与本地存储

## 边界

本阶段只建立类型、JSON 初值、服务及现有功能的接入，不新增业务页面。已有十页和路由保留。story.json 原始内容不变。用户自己的浏览器存储可以被本人修改，授权规则是本地应用逻辑约束，不是服务器级安全隔离。

## 八类对象

| 对象 | 模型及职责 |
|---|---|
| story | stories：稳定 ID、名称/类型/作者/简介、状态/阶段、不可变原始文本，独立 draft |
| world | 人物、关系、规则、场景、事件及按 arrival/suspense/decision 节点列出的知识引用 |
| assets | 类型、静态路径或 IndexedDB 文件 ID、引用、历史版本；上传文件另有名称/MIME/大小 |
| interactions | 节点、时间、场景、热点、行为、条件、状态变化及分支 ID |
| permissions | 场景、人物视角、二创节点、可编辑字段、可复用素材 ID；修改权限只作用于下次发布 |
| release | 本地发布记录、当前正式版本、时间、展示信息、不可覆盖的快照和素材版本引用 |
| progress | 来源作品/正式版本、时间/章节/节点、探索记录、视角、完成状态和视频素材 ID |
| branches | 独立二创 ID、来源作品/正式版本/节点、修改字段、创建时间、复用素材引用 |

## 文件职责

- `src/services/model.ts`：八类对象和兼容旧视图的类型，先定义于初值导入。
- `src/services/schema.ts`：Zod 字段、枚举、日期与文件引用校验。
- `src/data/model.json`：素材清单、初始身份、关系、规则、交互与授权；与既有 story.json 一起初始化测试数据。初始 release 是演示基线快照，不表示执行了线上发布。
- `src/services/data.ts`：初始化、迁移、引用检查、读写草稿、创建作品、本地发布、二创授权、节点知识及视频文件服务。
- `src/services/storage.ts`：唯一 localStorage 边界、JSON 异常恢复与容量提示。
- `src/services/files.ts`：IndexedDB `storyverse-files`（结构版本 1），files 对象仓库保存真实 Blob/File。blob URL 只在播放器挂载时生成、卸载时释放，不进入 localStorage。
- `src/store.tsx`：现有 React 视图的兼容层；写入前读取最新存档，监听跨标签 storage 事件；观众 hook 读取正式快照，创作者 hook 读取草稿。

## 本地读写与版本

所有新结构存于 `storyverse-db-v2`，顶层 schemaVersion 为 2；`-backup` 留存前一次存档，`-corrupt` 留存损坏数据以便人工恢复。遇到非法 JSON、字段类型/引用不匹配、未知结构版本，优先恢复有效备份，否则恢复初始数据并尝试兼容旧稿。异常会在已有全局状态提示处显示。旧 `storyverse-v1` 只读迁移，原值不删除，保留旧作品编辑和二创 ID；当时没有来源元数据的旧分支关联到演示基线版本。迁移后首次成功写入使用 v2。

草稿更新不改变正式快照。publishDraft 创建新 ID 和独立快照，保留历史；观众详情、展示及原作比较只读正式快照。此轮未增加发布 UI，不能在 C5 假装完成发布。多作品创建/编辑/发布服务已提供，当前页面仍只展示唯一测试作品。发布后主作品观看进度切到新版本并重置，旧二创继续引用旧正式版本。素材历史版本 ID 也被正式快照固定引用。

createRemix 校验节点与修改字段，保存时再次校验来源/权限/引用；重复 ID 不可覆盖。探索和视角受正式版本授权约束。角色知识在 arrival 不包含收纳秘密，suspense 和 decision 使用原作的信息差；全知线索卡始终是读者资料，不能作为角色事实来源。

## 容量与失败

localStorage 与 IndexedDB 都受浏览器配额、隐私模式和清理策略影响，不是云端永久存储。所有文件应自行备份。本地视频成功写入 IDB 后才保存元数据；元数据保存失败会尝试清理新文件并报告错误。缺失文件会提示重新导入。浏览器拒绝写入或配额不足时不更新 React 成功状态，也不宣称保存完成。备份会额外占用 localStorage 空间。

## 验证

服务测试覆盖初始化、保存再读、草稿/发布隔离、旧稿迁移、独立二创引用、越权拒绝、快照不可覆盖、未知版本/损坏数据恢复、容量错误与 IndexedDB 文件重新读取。既有 DOM 回归覆盖十页路由、原有交互及恢复。真实浏览器的配额策略、视频解码和 Pages 部署仍需独立验证；fake-indexeddb 测试不替代这些检查。
